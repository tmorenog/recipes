The ideas

What is an AI agent?

An AI agent is an AI model that works toward a goal by deciding, step by step, what to do next. It can use actions (also called tools): searching for a recipe, looking one up, saving it. After each action it reads the result and decides the next one, until the job is done or it gives up and explains why.

A chatbot answers a question once. An agent keeps going: it plans, acts, checks what happened and adjusts.

What is an action (or tool)?

Something the agent can do, such as “search recipes by ingredient” or “save a recipe”. An action is ordinary code that does one specific task and always does it the same way. The AI never runs code itself: it asks for an action, your app runs it, and the result goes back to the AI.

What’s the difference between an action and an agent?

An action performs one specific task. An agent decides which actions to use and in what order. In the Recipe Scout, step 1 builds the actions and step 2 adds the agent that uses them.

What is a multi-agent system, and why use several agents?

A system where several agents each do one job and pass their results on. In Meal Squad the Recipe Scout finds recipes, the Recipe Pricer prices them and the Meal Planner builds a five-day plan.

Splitting the work keeps each agent simple, lets each one be built, tested and improved on its own, and makes it easier to see where something went wrong.

What is the coordinator?

The part of the system that manages the handoffs. The agents never talk to each other directly: each one saves its work to the coordinator, which checks it, stores it and makes it available to the next agent. It also tells each agent how to work with it: the formats, the checks and the limits. It does not tell agents what to aim for; their goals come from your instructions.

What is MCP?

The Model Context Protocol: a standard way for an app to ask another system “what actions do you offer?” and then use them. Because the coordinator describes its own actions over MCP, your agent doesn’t need their names and formats written into its code.

What is the coordinator’s contract?

What an agent gets when it calls the coordinator’s get_contract action: its role in the system, the coordinator’s actions, the exact format to send, what the coordinator checks, the limits, and what happens to what it saves. Think of it as the terms for working with the coordinator.

Why does my agent do something different each time?

The AI decides what to do next, and its choices vary a little from run to run, like two people doing the same task differently. That’s normal. What matters is whether its choices make sense: look at what it tried, not only at the final result.

Is it a failure if my agent can’t finish?

No. An agent that stops and explains honestly why it couldn’t finish, for example because no five recipes fit the theme, is doing its job. An agent that invents recipes or numbers to look finished is the real failure.

Building in Lovable

What is Lovable, and what is Lovable Cloud?
Lovable builds a web app from plain-language descriptions. Lovable Cloud gives that app a backend: code that runs on a server rather than in the browser. Your agent and anything that uses the class key must run in the backend.
Do I have to use the sample prompts exactly?

No. They’re a starting point. Copy one as it is, or change it to make the app your own. Paste one step at a time and check the result before moving on.

What is the class key, and why does it go in a “secret”?

The class key is the password that lets your agent talk to the coordinator. Your instructor gives it to you. Lovable stores it as a secret, which only your app’s backend can read. Never paste it into a prompt, your page or a chat: anyone who sees it could save things in the class’s name.

What is the group name for?

It labels everything your agents save, so you can find your work on the Coordinator page. Choose one in Before you start and use it for every agent; the sample prompts fill it in.

A step didn’t work. What should I do?

Tell Lovable what you expected and what happened instead, and paste any error message you see. Look at what the agent did (its trace) before changing anything. If a change made things worse, ask Lovable to go back to the previous version. You don’t need to start over.

When something goes wrong

“Missing or wrong class key” (error 401)

Re-enter the CLASS_KEY secret in Lovable, then ask: “Check that every request to the coordinator sends the header Authorization: Bearer followed by the CLASS_KEY secret.”

An error about “X-Group” (error 400)

The coordinator needs your group name on every request. Ask Lovable: “Send our group name in the header X-Group on every request to the coordinator.”

The coordinator rejected a recipe or a plan

That’s the coordinator doing its job, and the rejection lists every problem. A good agent reads the reasons, fixes them and tries again. Common reasons:

  • a field is missing or in the wrong format;
  • the recipe doesn’t match TheMealDB (the coordinator checks that every recipe is real);
  • your group already picked that recipe for the same theme;
  • your group reached the class’s limit, or tried too many times in a minute.

If the agent keeps making the same mistake, paste the reason into Lovable: “The coordinator rejects our recipes with: … Make sure the agent passes the rejection back to the AI.”

A “CORS” error in the browser

Your page is calling the coordinator directly from the browser. Ask Lovable: “Move every call to the coordinator into a backend function.”

The agent stops early or goes round in circles

Look at the last few steps it took. Tell Lovable what it did and what it should have done instead, or make its instructions clearer.

Where can I see what my agent actually did?

On the Coordinator page: every request your agent sends and the coordinator’s answer, live, including rejections and why. Filter by your group name.

The data

Where do the recipes come from?

From TheMealDB, a free public recipe database. The coordinator only accepts recipes that exist there, with their real names and ingredients.

Where do the prices come from, and what does “estimated” mean?

The Recipe Pricer builds a shopping cart for each recipe with real prices from Kroger, a US supermarket chain. When Kroger has no suitable product for an ingredient, the Pricer estimates its price and labels it as estimated.

Does the coordinator check nutrition?

No. Making the week nutritious is a goal you give your Meal Planner in its instructions. The coordinator only checks what it can work out from real data: the cost against the budget, the cuisines, the categories and the vegetarian dinner. If your agent estimates nutrition from the ingredients, those are rough estimates for the exercise, not dietary advice.
