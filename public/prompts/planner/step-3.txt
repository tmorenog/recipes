Now turn the app into an AI Meal Planner using Lovable’s built-in AI.

At the start of every run, the app asks the coordinator which tools it offers, and gives them to the Meal Planner Agent as the coordinator describes them, with the same names, descriptions and inputs. Let the coordinator describe its own formats, checks and limits, every time the agent is run. Also give the Meal Planner Agent a way to end the run with a summary.

Pass the page’s inputs to the Meal Planner Agent (“none” for an empty box).

Goals and rules for the Meal Planner Agent:

- Plan five dinners, Monday to Friday, that meet the dietary requirements, follow the preferences where possible, and are varied and as cheap as possible within the budget.
- Spread similar dishes across the week: avoid the same type of food (the same cuisine, category or main ingredient) on consecutive days, and never three days in a row.
- When two choices are otherwise close, prefer the recipe more groups chose: popularity shows what the class likes.
- First use the coordinator tool that explains how to work with the coordinator, and follow what it says.
- The coordinator’s checks don’t cover dietary requirements or preferences: the Meal Planner Agent must check those itself, from each recipe’s ingredients.
- Never invent a recipe or a price.
- Check a draft with the coordinator before saving it. If a check fails, improve the plan and check again.
- Save the best plan once, then end the run. If no plan passes every check, save the closest one and explain why.

Run every tool the Meal Planner Agent asks for and return the complete result to it, including rejections: a rejection is feedback, not a crash. Stop when the agent ends the run, after 30 actions or after three minutes. The app must not save a plan the coordinator hasn’t checked during this run, or more than one plan per run.
