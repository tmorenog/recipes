Now turn the app into an AI Meal Planner using Lovable’s built-in AI.

At the start of every run, get the coordinator’s tools from the MCP server and give them to the Planner Agent exactly as the coordinator describes them. Don’t write the coordinator’s tool names, formats, checks or limits into the app. Also give the Planner Agent a way to end the run with a summary.

Pass the page’s inputs to the Planner Agent (“none” for an empty box). The budget on the page is per person per dinner; the coordinator expects the budget for all five dinners, so multiply it by 5.

Goals and rules for the Planner Agent:

- Plan five dinners, Monday to Friday, that meet the dietary requirements, follow the preferences where possible, and are nutritious, varied and as cheap as possible within the budget.
- First use the coordinator tool that explains how to work with the coordinator, and follow what it says.
- Use only recipes from the coordinator that have a price. If two are equally good, prefer the one more groups picked.
- Let the coordinator add up the costs. Never invent a recipe, a price or a number.
- Check a draft with the coordinator before saving it. If a check fails, improve the plan and check again.
- Save the best plan once, then end the run. If no plan passes every check, save the closest one and explain why. If the dietary requirements can’t be met, save nothing and explain why.
- If the coordinator rejects something, fix it and try again. If it says to wait or that a limit has been reached, stop and explain.

Run every tool the Planner Agent asks for and return the complete result to it, including rejections: a rejection is feedback, not a crash. Stop when the Planner Agent ends the run, after 30 actions or after three minutes, and record why. The app must not save a plan the coordinator hasn’t checked during this run, or more than one plan per run.

Update the page:

- “Plan my week” starts the Planner Agent and is disabled while it works
- “What the Planner Agent is doing” shows its actions, the coordinator’s answers and errors as they happen, with the actions used and the time left; make failed checks and rejections easy to spot without showing them as crashes
- “The week” shows the saved plan: for each day the photo, name, cost per serving, why it was chosen and a link to the recipe on TheMealDB (https://www.themealdb.com/meal/MEAL_ID); below the days, the week’s cost against the budget and each check with ✓ or ✗
- A “Shopping list”: the ingredients for the five dinners, each listed once, with the week’s total price from the coordinator
- The outcome area: “Valid plan found”, “No feasible plan found” or “Run failed”, with the explanation
- A link to the class Coordinator page ({{SITE}}/coordinator), credit to TheMealDB for the photos, and a history of past runs that can be reopened
- Keep the Step 2 sections as collapsible sections

Save what happens (actions, results, errors), but not the AI model’s private reasoning.
