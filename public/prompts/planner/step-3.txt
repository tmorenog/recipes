Now turn the app into an AI Meal Planner using Lovable’s built-in AI.

At the beginning of every run, ask the MCP server which tools are currently available. Give those tools to the Planner Agent exactly as the coordinator describes them. Preserve their names, descriptions and input requirements.

Do not write the coordinator’s tool names, plan format, checks or limits into the app.

Also give the Planner Agent a way to end the run and summarize what happened.

Pass the budget, the dietary requirements and the preferences from the page to the Planner Agent. Write “none” for an empty box.

These are the goals and rules for the Planner Agent:

- Plan five dinners, Monday to Friday, within the budget per person for the five dinners.
- Every dinner must meet the dietary requirements. Follow the preferences where possible.
- Choose dinners that are nutritious and balanced, varied (different cuisines and main ingredients), and as cheap as possible within the budget.
- Begin each run by using the coordinator tool that explains how to work with the coordinator.
- Follow the formats, checks and limits returned by the coordinator.
- Use only recipes from the coordinator that already have a price.
- Estimate the nutrition of one serving of each dinner from its ingredients and number of servings, and say that these are estimates.
- When two choices are otherwise equally good, prefer the one more groups picked, then the cheaper one.
- Let the coordinator add up the costs. Never calculate or guess them.
- Ask the coordinator to check a draft before saving it. If a check fails, change the plan and check again.
- When the plan is as good as it can be, save it once through the coordinator, then end the run.
- If no plan can pass every check, save the closest one and explain which checks can’t be met and why. If no plan can meet the dietary requirements, save nothing and explain why.
- If the coordinator says to wait or that a limit has been reached, stop and explain instead of retrying.
- Treat a failed check or a rejection as useful feedback, not as an application failure.
- Never invent a recipe, a price or a number.

Run every tool requested by the Planner Agent and return the complete result to it. If the coordinator returns a tool result marked as an error, pass the complete result back so the Planner Agent can correct its work. Do not treat it as a crashed run.

Continue until the Planner Agent ends the run, uses 30 actions or reaches three minutes. Record why it stopped.

The app must enforce these rules:

- A plan cannot be saved unless the coordinator checked the same plan during this run.
- No more than one plan can be saved per run.
