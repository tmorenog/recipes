Agent 2

Build the Meal Planner

An agent that takes the recipes the Scouts saved, prices every ingredient at a real Kroger store, and plans five dinners that are balanced and within budget, with a shopping list.

The goal

Your Planner is done when: you enter a ZIP code, a budget and a number of people, press a button, and a five-dinner plan with a Kroger shopping list appears on the Database page under your group. The five recipes it used are marked as processed.

  • It learns the steps, rules and plan format from the coordinator (get_expectations) instead of having them written into its code
  • Prices come from a real Kroger store near the ZIP code
  • The maths is done by code, not guessed by the AI
  • The plan follows the balance rules and says which ones passed
  • You can see every step: what it read, what it priced, why it chose each meal

Build it in Lovable

Paste each step into Lovable one at a time, and check the result before moving on. As with the Scout, the app uses Lovable Cloud and Lovable’s built-in AI. The Kroger lookups go through the coordinator’s own Kroger account, so the only key you need is the class key.

The class key never goes in a prompt. Step 1 asks Lovable to create a secret. Lovable then shows a secure box where you paste the key.

Pick one name for your group and use it for both agents, e.g. team-3. It labels everything your agents save.

Step 3 of 5Add the calculator tools

Add two calculator tools in plain code, so the AI never does arithmetic itself. 1. price_ingredient(amount, unit, package_size, package_price_usd): what a recipe's quantity costs. Parse package sizes like "16.9 fl oz", "3 lb", "12 ct" or "each", and convert between weight, volume and count units. Between volume and weight, assume 1 ml weighs 1 g and say so in "note". A null amount ("to taste") costs 0; a null unit means a count ("2 eggs"). If the units can't be converted, return an error instead of guessing. Return { fraction_of_package, cost_used_usd, packages_to_buy, cost_to_buy_usd, note }, with money rounded to cents. 2. plan_totals(meals, shopping_list): set each meal's cost_per_serving_usd = cost_used_usd ÷ servings, and total_cost_usd = the sum of quantity × unit_price_usd over the shopping list, rounded to cents. Test it

It works when…

  • The trace starts with get_expectations
  • A run with ZIP 45202, $60 and 4 people saves a plan
  • The plan appears on the Database page under Meal plans, with a shopping list
  • The five recipes now show as processed, by your group
  • Every price in the trace came from a Kroger search

Now try to break it

  • A tiny budget: $15 for 4 people. Does it swap meals, or say it can’t be done?
  • Not enough recipes: what happens when fewer than 5 are new?
  • An odd ingredient Kroger doesn’t sell. Does it try another search, or make up a price?
  • A tight limit: set the limit to 20 tool calls. What does it do when it runs out?
  • Two costs: compare the plan’s total with the sum of cost used. Why are they different?

Reference

How it works
  1. Read the new recipes

    Ask the coordinator for recipes nobody has used yet. Recipes from every group are shared: once a Planner marks a recipe processed, it disappears from everyone’s “new” list.

  2. Pick a store

    Kroger prices depend on the store, so find one near the ZIP code and use it for every search.

  3. Price the ingredients

    For each ingredient, search Kroger, choose the product that matches, and let code work out what the recipe’s share of it costs.

  4. Estimate nutrition

    The AI estimates calories, protein, fibre and sodium per serving from the ingredients. These are estimates, and the plan says so.

  5. Choose five dinners

    Balanced by your rules, within budget. Recipes that share ingredients make the shopping list cheaper.

  6. Save and hand back

    Save the plan to the coordinator, fix anything it rejects, then mark the five recipes as processed.

The coordinator’s MCP server

{{SITE}}/api/mcp?agent=planner offers the Planner these tools. Every request carries Authorization: Bearer <class key> and X-Group: {{GROUP}}.

ToolDoes
get_expectationsThe steps, the balance rules, every field save_meal_plan accepts, and the checks it runs
list_recipesRecipes nobody has used yet (status: "new"), from every group
find_kroger_storesUp to 5 stores near a ZIP code: store_id, name, address
search_kroger_productsProducts at one store: product_id, description, size, price_usd, promo_price_usd
save_meal_planSaves the plan, or rejects it with every reason at once
mark_processedMarks a recipe as used, so it drops out of everyone’s “new” list

Your app adds two calculator tools of its own, price_ingredient and plan_totals, so the model chooses and code calculates.

Kroger allows a limited number of searches per day for the whole class. Search once per ingredient and reuse the answer: the same search at the same store gives the same prices.

Costing a recipe

A recipe needs “2 tbsp olive oil”. Kroger sells a 16.9 fl oz bottle for $7.99. What does the recipe cost? There are two honest answers, and your plan uses both:

Cost used

The share of the package the meal uses: 2 tbsp is 1 fl oz, 1/16.9 of the bottle, about $0.47. This is the meal’s real food cost. It goes in cost_used_usd.

Cost to buy

What you pay at the till: the whole bottle, $7.99. The shopping list uses this. Its total is total_cost_usd, which is what your budget is about.

Unit conversion (tablespoons to fluid ounces, grams to pounds) is exactly the kind of arithmetic AI models get wrong. Step 3 gives your agent small calculator tools, so the model decides which product to use and code works out how much it costs.

What “balanced” means

Your agent needs rules it can check, not just “make it healthy”. Start with these, then discuss as a group whether you’d change them. These are classroom rules, not dietary advice.

Each dinner, per serving

  • 400 to 800 calories
  • At least 20 g protein
  • At least 5 g fibre
  • Under 1,500 mg sodium

Across the five dinners

  • No main protein more than twice
  • At least 3 different cuisines, when the recipes allow
  • At least one vegetable-forward dinner
  • The shopping list total is within the budget

Your agent reads these rules from get_expectations. To use different ones, add them to the model’s instructions in step 4: the coordinator tells the agent that your rules win.

The meal plan format (your agent reads this from get_expectations)
FieldWhat goes in it
summaryWhy these five meals: balance, cost, trade-offs, anything estimated
budget_usdThe budget you were given (optional)
store_idThe Kroger store the prices came from
total_cost_usdThe shopping list total: the sum of quantity × unit_price_usd
mealsExactly 5, each with day (1 to 5, all different), recipe_id (from the coordinator; all different), servings, cost_used_usd, cost_per_serving_usd (= cost used ÷ servings), nutrition_per_serving with calories, protein_g, fiber_g, sodium_mg
shopping_listOne line per Kroger product: item, kroger_product_id, description, size, quantity (packages), unit_price_usd, recipe_ids (which of the 5 meals use it)
rule_checksEach rule you checked: rule, passed (true/false), detail

The coordinator rejects a plan whose numbers don’t add up (to within 5 cents), that repeats a day or a recipe, or that uses a recipe id it doesn’t know. Going over budget is allowed but flagged.

When things go wrong
You seeTry
“total_cost_usd is …, but the shopping list adds up to …”The agent did the maths itself. Ask Lovable: “Make sure the agent always calls plan_totals before save_meal_plan and uses its numbers.”
“no recipe has the id …”The agent invented or mistyped an id. Ask Lovable to use only ids returned by list_recipes.
“Kroger is limiting requests”The class has used a lot of searches. Wait a minute, and check the agent reuses earlier search results.
“Kroger prices are not set up yet”Tell your instructor: the coordinator needs its Kroger credentials.
401, 400 about X-Group, or a CORS errorSame fixes as the Scout: check the class key on the Welcome page, send X-Group: {{GROUP}}, and make sure calls happen in a backend function.
The agent never calls get_expectations, or the tool is missing“Load the coordinator’s tools with tools/list from {{SITE}}/api/mcp?agent=planner and give all of them to the model, together with price_ingredient and plan_totals.”
