Build the Meal Planner

An agent that takes the recipes the Scouts saved, prices every ingredient at a real Kroger store, and plans five dinners that are balanced and within budget, with a shopping list.

The goal

Your Planner is done when: you enter a ZIP code, a budget and a number of people, press a button, and a five-dinner plan with a Kroger shopping list appears on the Database page under your group. The five recipes it used are marked as processed.

  • Prices come from a real Kroger store near the ZIP code
  • The maths is done by code, not guessed by the AI
  • The plan follows your balance rules and says which ones passed
  • You can see every step: what it read, what it priced, why it chose each meal

How it works

  1. Read the new recipes

    Ask the coordinator for recipes nobody has used yet. Recipes from every group are shared: once a Planner marks a recipe processed, it disappears from everyone’s “new” list.

  2. Pick a store

    Kroger prices depend on the store, so find one near the ZIP code and use it for every search.

  3. Price the ingredients

    For each ingredient, search Kroger, choose the product that matches, and let code work out what the recipe’s share of it costs.

  4. Estimate nutrition

    The AI estimates calories, protein, fibre and sodium per serving from the ingredients. These are estimates, and the plan says so.

  5. Choose five dinners

    Balanced by your rules, within budget. Recipes that share ingredients make the shopping list cheaper.

  6. Save and hand back

    Save the plan to the coordinator, fix anything it rejects, then mark the five recipes as processed.

Costing a recipe

A recipe needs “2 tbsp olive oil”. Kroger sells a 16.9 fl oz bottle for $7.99. What does the recipe cost? There are two honest answers, and your plan uses both:

Cost used

The share of the package the meal uses: 2 tbsp is 1 fl oz, 1/16.9 of the bottle, about $0.47. This is the meal’s real food cost. It goes in cost_used_usd.

Cost to buy

What you pay at the till: the whole bottle, $7.99. The shopping list uses this. Its total is total_cost_usd, which is what your budget is about.

Unit conversion (tablespoons to fluid ounces, grams to pounds) is exactly the kind of arithmetic AI models get wrong. The prompts below give your agent a small calculator tool, so the model decides which product to use and code works out how much it costs.

What “balanced” means

Your agent needs rules it can check, not just “make it healthy”. Start with these, then discuss as a group whether you’d change them. These are classroom rules, not dietary advice.

Each dinner, per serving

  • 400 to 800 calories
  • At least 20 g protein
  • At least 5 g fibre
  • Under 1,500 mg sodium

Across the five dinners

  • No main protein more than twice
  • At least 3 different cuisines, when the recipes allow
  • At least one vegetable-forward dinner
  • The shopping list total is within the budget

The meal plan format

FieldWhat goes in it
summaryWhy these five meals: balance, cost, trade-offs, anything estimated
budget_usdThe budget you were given (optional)
store_idThe Kroger store the prices came from
total_cost_usdThe shopping list total: the sum of quantity × unit_price_usd
mealsExactly 5, each with day (1 to 5, all different), recipe_id (from the coordinator; all different), servings, cost_used_usd, cost_per_serving_usd (= cost used ÷ servings), nutrition_per_serving with calories, protein_g, fiber_g, sodium_mg
shopping_listOne line per Kroger product: item, kroger_product_id, description, size, quantity (packages), unit_price_usd, recipe_ids (which of the 5 meals use it)
rule_checksEach rule you checked: rule, passed (true/false), detail

The coordinator rejects a plan whose numbers don’t add up (to within 5 cents), that repeats a day or a recipe, or that uses a recipe id it doesn’t know. Going over budget is allowed but flagged.

Prompt 2 of 5Add the coordinator and Kroger tools

Create backend tools the agent will use. Plain code only, no AI yet. Each returns JSON. Every call to the coordinator sends the header "Authorization: Bearer " + the COORDINATOR_KEY secret. 1. list_recipes(theme optional, group optional) -> GET {{SITE}}/api/recipes?status=new&limit=50, adding &theme= or &group= when given. Prompt 3 of 5Add the calculator tools

Add two calculator tools in plain code, so the AI never does arithmetic itself. 4. price_ingredient(amount, unit, package_size, package_price_usd) Works out what a recipe's quantity of an ingredient costs. - Parse package_size text like "16.9 fl oz", "3 lb", "12 ct", "each". - Convert between units in the same family. Weight: g, kg, oz, lb. Volume: ml, l, tsp, tbsp, cup, fl oz, pint, quart, gallon (1 tbsp = 3 tsp = 0.5 fl oz; 1 cup = 8 fl oz). Count: each, ct. - If the recipe uses volume and the package is sold by weight (or the other way round), assume 1 ml weighs 1 g, and say so in "note". - If amount is null ("to taste"), return cost_used_usd 0 and note "to taste". - If the unit is null (e.g. "2 eggs"), treat the amount as a count. - If the units can't be converted, don't guess: return an error saying why. Return { fraction_of_package, cost_used_usd, packages_to_buy, cost_to_buy_usd, note }. Round money to cents. 5. plan_totals(meals, shopping_list) - For each meal set cost_per_serving_usd = cost_used_usd ÷ servings, rounded to cents. - Set total_cost_usd = the sum of quantity × unit_price_usd over the shopping list, rounded to cents. Return the updated meals and total_cost_usd. Test price_ingredient with: 2 tbsp olive oil from a "16.9 fl oz" bottle at 7.99 (expect about 0.47 used, 7.99 to buy), and 300 g onions from a "3 lb" bag at 3.49.

Prompt 4 of 5Add saving and the agent loop

Add two more coordinator tools (same Authorization header): 6. save_meal_plan(plan) -> POST {{SITE}}/api/meal-plans with the plan as JSON. Return the status and the reply. A 400 reply has an "errors" list: pass it back to the agent. 7. mark_processed(recipe_id) -> POST {{SITE}}/api/recipes/RECIPE_ID/processed. Then add the agent: a backend function run-planner that uses Lovable AI with tool calling and all seven tools. It takes the ZIP code, budget and people per meal from the page. - Loop: send the instructions below and the tool definitions, run each tool the model asks for, send back the result, repeat. - Stop when the model calls finish(summary), or after 80 tool calls, or after 5 minutes. Record why it stopped. - Save every step to a table agent_steps (run_id, step number, kind: thought / tool_call / tool_result / error / final, tool name, input, output, time) as it happens. Instructions for the model: "You are Meal Planner. Plan 5 dinners, one per day for days 1 to 5, for PEOPLE people, from the coordinator's new recipes, priced at a Kroger store near ZIP, within a budget of BUDGET US dollars. 1. Call list_recipes. If there are fewer than 5 recipes, say so and finish. 2. Call find_kroger_stores and use the first store for every search. 3. For each promising recipe, price its ingredients. Scale quantities from the recipe's est_servings to PEOPLE. Skip pantry staples (salt, pepper, water, cooking oil, dried herbs and spices): assume they're at home and cost 0, and mention them in the summary. For everything else, search Kroger, choose the product that matches the ingredient's form (garlic, not garlic powder) and a sensible size, and call price_ingredient. Use the promo price when there is one. If nothing matches, try a simpler search term. If still nothing, choose another recipe. 4. Estimate each recipe's nutrition per serving: calories, protein_g, fiber_g, sodium_mg. Say in the summary that these are estimates. 5. Choose 5 recipes that follow these rules: per serving 400 to 800 calories, at least 20 g protein, at least 5 g fibre, under 1,500 mg sodium; across the week no main protein more than twice, at least 3 cuisines when possible, at least one vegetable-forward dinner; shopping list within budget. Prefer recipes that share ingredients. If no set passes every rule, pick the best one and say which rules failed. 6. Build the shopping list: one line per Kroger product, with the total number of packages needed across all meals and the recipe_ids that use it. 7. Call plan_totals, then save_meal_plan with: summary, budget_usd, store_id, total_cost_usd, meals (day, recipe_id, servings = PEOPLE, cost_used_usd, cost_per_serving_usd, nutrition_per_serving), shopping_list (item, kroger_product_id, description, size, quantity, unit_price_usd, recipe_ids), and rule_checks (one per rule: rule, passed, detail). 8. If save_meal_plan returns errors, fix every one and save again. 9. Once saved, call mark_processed for each of the 5 recipes, then finish with a short summary."

Test it

It works when…

  • A run with ZIP 45202, $60 and 4 people saves a plan
  • The plan appears on the Database page under Meal plans, with a shopping list
  • The five recipes now show as processed, by your group
  • Every price in the trace came from a Kroger search

Now try to break it

  • A tiny budget: $15 for 4 people. Does it swap meals, or say it can’t be done?
  • Not enough recipes: what happens when fewer than 5 are new?
  • An odd ingredient Kroger doesn’t sell. Does it try another search, or make up a price?
  • Two costs: compare the plan’s total with the sum of cost used. Why are they different?

When things go wrong

You seeTry
“total_cost_usd is …, but the shopping list adds up to …”The agent did the maths itself. Ask Lovable: “Make sure the agent always calls plan_totals before save_meal_plan and uses its numbers.”
“no recipe has the id …”The agent invented or mistyped an id. Ask Lovable to use only ids returned by list_recipes.
“Kroger is limiting requests”The class has used a lot of searches. Wait a minute, and check the agent reuses earlier search results.
“Kroger prices are not set up yet”Tell your instructor: the coordinator needs its Kroger credentials.
401 or a CORS errorSame fixes as the Scout: check your key on the Welcome page, and make sure calls happen in a backend function.
