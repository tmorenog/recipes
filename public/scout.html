Agent 1

Build the Recipe Scout

An agent that takes a theme, searches a real recipe database, chooses five recipes that fit, and saves them to the coordinator for the Meal Planners to use.

Build it in stages

You’ll build Recipe Scout in stages. First, you’ll create a simple interface. Then you’ll connect it to real recipe information, add an AI agent, and connect that agent to the class coordinator.

You will change and rework parts of the app as you go. That is intentional. The goal is to understand how the system develops—not to build the perfect application on the first attempt.

In this exercise, an action is something the agent can do, such as searching for a recipe or saving one. These actions are sometimes called tools.

Each step has a goal, a sample prompt to copy into Lovable (use it as it is or change it), what you should see, and things you can try before moving on.

Step 0 · warm-upBuild your first page

Goal

See how quickly Lovable can turn a plain-language description into an interface. There is no AI, backend or recipe data yet.

Sample prompt

What you should see

A finished-looking page with a theme input, example themes, a button and an empty results area. It is normal that the button does nothing.

Things you can try

  • Ask Lovable to change the colors or visual style.
  • Add another example dinner theme.
  • Change the title or button text.
  • Ask Lovable to make one small layout improvement.

Don’t spend too long polishing. You will change the interface as the agent develops.

Step 1Connect to real recipe information

Goal

Give the application reliable actions for finding real recipes. These are ordinary backend functions—not an AI agent.

Sample prompt

What you should see

  • The original Recipe Scout page
  • A temporary Recipe Tool Lab
  • Real recipes returned from TheMealDB
  • Short summaries from searches
  • Ingredients and instructions when retrieving a complete recipe
  • No AI agent yet

Things you can try

  • Search by name for Arrabiata.
  • Search using the ingredient chicken.
  • Browse the category Vegetarian or the cuisine Italian.
  • Search for something that probably does not exist.

Notice the difference between an action and an agent. An action performs one specific task. An agent decides which actions to use and in what order.

Step 2Add the Recipe Scout agent

Goal

Add an AI agent that decides how to search, examines the results and selects five recipes. This is the first step with a “What the Scout is doing” panel.

Sample prompt

What you should see

  • The Scout deciding how to search

  • Five selected recipes with photos and explanations

Things you can try

  • Comfort food
  • 20-minute vegetarian dinners
  • Vegan dinners with beef

The important question is not only “Did it find five recipes?” Also ask: “What did it try, and did its choices make sense?”

Step 3Join the multi-agent system

Goal

Connect Recipe Scout to the class coordinator so its recipes can be checked, saved and passed to other agents, such as the Recipe Pricer and the Meal Planner.

Recipe Scout → Coordinator → Recipe Pricer

The Scout does not send recipes directly to the Recipe Pricer. It sends them to the coordinator. The coordinator checks each recipe, saves accepted recipes and makes them available to the next agent.

The Scout talks to the coordinator through MCP, a standard way for an app to ask another system what actions it offers and then use them. Each use is a request and an answer:

Step 3aConnect to the coordinator

Goal

Connect the app to the coordinator’s MCP server and look at the actions (tools) it offers.

The class key never goes in a prompt. This step asks Lovable to create a secret. Lovable then shows a secure box where you paste the key. The prompt uses your group name from Before you start on the Welcome page: {{GROUP}}.

Sample prompt

What you should see

  • A Coordinator connection section
  • A successful connection message
  • The tools provided by the coordinator
  • A plain-language description of what each tool does
  • The information required to use each tool
  • No change to the Scout’s behavior yet

Things you can try

  • Read the description of each coordinator tool, and the information each one requires.
  • Look for your connection on the Coordinator page.
  • Discuss which tool the Scout should use first.
  • Discuss which tool it would use to hand off a recipe.

MCP allows an application to discover what another system can do. The coordinator describes its tools, so Recipe Scout does not need to have their names and input formats written into its code.

Step 3bLet the Scout use the coordinator

Goal

Give the discovered coordinator tools to Recipe Scout. The Scout will learn how to work with the coordinator, submit recipes, respond to rejections and complete the handoff to the Recipe Pricer.

Sample prompt

What you should see

  • The Scout discovers the coordinator tools at the beginning of the run.
  • It uses the appropriate tool to learn how to work with the coordinator.
  • It follows the formats, rules and limits returned by the coordinator.
  • It searches and examines real recipes through TheMealDB.
  • It submits recipes to the coordinator.
  • Accepted and rejected submissions are clearly identified.
  • The Scout tries to correct rejected recipes.
  • Five accepted recipes appear on the Coordinator page.
  • The Recipe Pricer queues or begins processing the accepted recipes.

Things you can try

  • Run the same theme twice and observe duplicate handling.
  • Try a contradictory theme.
  • Open a rejected exchange on the Coordinator page and compare it with an accepted one.
  • Change one Scout instruction and compare its behavior.

Reference

How it works

An agent is a loop. The AI model decides which action (tool) to use next, your app runs it, and the result goes back to the model, until the job is done. The Scout has two kinds of actions: its own, for TheMealDB (steps 1 and 2), and the coordinator’s (step 3).

Finding recipes: TheMealDB

A free recipe database; the developer key is 1. Your app names these actions itself, so its names may differ. Base address https://www.themealdb.com/api/json/v1/1/. It publishes notes for AI agents: AGENTS.md, SKILL.md and the API documentation.

Saving recipes: the coordinator’s MCP server

MCP (Model Context Protocol) lets an agent discover tools and their rules from a server instead of having them written into its code. {{SITE}}/api/mcp?agent=scout offers the Scout two tools:

ToolDoes
get_expectationsHow to work with the coordinator: the Scout’s role in the system, every field save_recipe accepts and where its value comes from, what is checked, the limits, what happens to a saved recipe, and an example
save_recipeSaves one recipe under your group, or rejects it with every reason at once

Every request carries Authorization: Bearer <class key> and X-Group: {{GROUP}}. Under the hood it’s one POST per call:

POST {{SITE}}/api/mcp?agent=scout
{ "jsonrpc": "2.0", "id": 1, "method": "tools/call",
  "params": { "name": "get_expectations", "arguments": {} } }
The recipe format (your agent reads this from get_expectations)

The contract between your Scout and every Meal Planner. The coordinator rejects anything that doesn’t match, including fields that aren’t listed here.

FieldRequiredWhat goes in it
themeyesThe theme, exactly as typed
meal_idyesTheMealDB’s idMeal, e.g. "52772"
nameyesstrMeal
category, cuisinenostrCategory, strArea
ingredientsyesOne item per strIngredientN: name, amount (a positive number, or null for “to taste”), unit (or null for things you count, like eggs), raw (strMeasureN as written, or "" when TheMealDB gives no measure)
instructionsyesstrInstructions (at least 20 characters)
est_minutes, est_servingsyesThe agent’s estimates: whole numbers
image_url, source_urlnostrMealThumb, strSource (http/https, or null)
why_chosenyesOne sentence: why this recipe fits the theme

A rejected recipe gets every problem at once, for example: est_servings must be at least 1, why_chosen is empty, unknown field: calories.

When things go wrong
You seeTry
401 “Missing or wrong class key”Re-enter the CLASS_KEY secret. Then ask Lovable: “Check that every request to the coordinator sends Authorization: Bearer followed by the CLASS_KEY secret.”
400 about X-Group“Send the header X-Group: {{GROUP}} on every request to the coordinator.”
The agent never asks the coordinator how to work with it, or the tool is missing“At the start of every run, load the coordinator’s tools from {{SITE}}/api/mcp?agent=scout and give all of them to the Scout, exactly as described.”
A rejection with reasonsThat’s the coordinator doing its job. If the agent keeps making the same mistake, paste the reason into Lovable: “The coordinator rejects our recipes with: … Make sure the agent passes the rejection text back to the model.”
“unknown field: …”The agent added a field. Ask Lovable to send exactly what get_expectations lists.
A CORS error in the browser consoleThe page is calling the coordinator directly. “Move every call to the coordinator into a backend function.”
The agent stops early or loopsLook at the last few steps of the trace. Tell Lovable what it did and what it should have done instead.
Without MCP: save over REST

The same checks are also available as a plain REST address, if MCP gives you trouble.

POST {{SITE}}/api/recipes
Authorization: Bearer <class key>
X-Group: {{GROUP}}
Content-Type: application/json

{ …the recipe… }
AnswerMeans
201Saved. The reply includes the stored recipe.
400Something’s missing or wrong. errors lists every problem.
409Your group already saved this recipe for this theme.
401Missing or wrong class key. (400 if X-Group is missing.)

Over REST the agent can’t read the rules itself, so the recipe format has to go into the model’s instructions.
