Agent 1

Build the Recipe Scout

You type a theme. The agent searches TheMealDB, picks five real recipes that fit, and saves them to the coordinator for the Meal Planners.

You’re done when you press one button and five fitting recipes appear on the Database page under your group, and you can see every step the agent took to get them.

TheMealDB publishes instructions written for AI agents: AGENTS.md, SKILL.md and the API documentation. The prompts below tell Lovable to read them, so you don’t have to spell out the API.

Build it in Lovable

One name for your group, used by both agents, e.g. team-3. The prompts below fill it in.

2. Paste the prompts one at a time, and check the result before the next. The class key never goes in a prompt: when Lovable asks for the COORDINATOR_KEY secret, paste the key into the secure box it shows.

Prompt 1 of 3The app and its tools

Build a web app called "Recipe Scout": an AI agent that finds real recipes for a theme and saves them to our class coordinator. Enable Lovable Cloud. Add a secret named COORDINATOR_KEY and ask me for its value. Only backend functions may use it. Read these pages and follow them when using TheMealDB: - https://www.themealdb.com/AGENTS.md - https://www.themealdb.com/SKILL.md - https://www.themealdb.com/documentation Use the free test key (base address https://www.themealdb.com/api/json/v1/1/). Create backend tools for the agent: 1. search_meals: search by name, or filter by ingredient, category or cuisine 2. get_recipe(meal_id): the full recipe (filters only return id, name and photo) 3. save_recipe(recipe): POST {{SITE}}/api/recipes with the headers "Authorization: Bearer " + COORDINATOR_KEY, "X-Group: {{GROUP}}" and "Content-Type: application/json". Return the status and reply exactly as received. A 400 or 409 reply has an "errors" list: pass it back to the agent, don't treat it as a crash. The page: a theme box (with the examples "cheap weeknight vegetarian dinners" and "15-minute lunches"), a "Run Recipe Scout" button, and two panels: "What the agent is doing" and "Saved recipes". Test search_meals and get_recipe once and show me the results. Don't call save_recipe yet.

Prompt 2 of 3The agent

Add a backend function run-scout: an agent loop using Lovable AI with tool calling and the three tools. Run a tool when the model asks, send back the result, repeat. Stop when the model calls finish(summary) or after 25 tool calls. Save every step (thought, tool call, result, error) to a table agent_steps as it happens. Instructions for the model: "You are Recipe Scout. Find 5 real recipes on TheMealDB that fit the theme and save each one with save_recipe. - Try different searches. Always call get_recipe before saving. Never invent a recipe, ingredient or quantity. - Save exactly these fields and no others: theme (exactly as given), meal_id (idMeal), name (strMeal), category (strCategory), cuisine (strArea), ingredients, instructions (strInstructions), est_minutes, est_servings, image_url (strMealThumb), source_url (strSource, or null), why_chosen. - ingredients: one item per non-empty strIngredientN: { name (lowercase), amount (the number in strMeasureN, or null), unit (e.g. g, tbsp, cup, or null for things you count), raw (strMeasureN as written) }. - est_minutes and est_servings: whole numbers you estimate. why_chosen: one sentence on why it fits the theme. - Pick varied recipes. If save_recipe returns errors, fix every one and try again; if it's already saved, pick another. - Call finish when 5 are saved, or explain why the theme can't be met."

Prompt 3 of 3Show it working

Connect the page to run-scout. "Run Recipe Scout" starts a run and is disabled until it ends. - "What the agent is doing" shows the steps live: tool name and inputs, results collapsed (click for JSON), rejections in red, and a counter like "12 / 25 tool calls". - "Saved recipes" shows each accepted recipe: photo, name, cuisine, time and why_chosen. - Add a link "See it on the class database" to {{SITE}}/database

Test it, then try to break it

It works when…

  • “cheap weeknight vegetarian dinners” saves 5 varied recipes
  • They show on the Database page under your group
  • The trace shows each search, look-up and save

Try to break it

  • Run the same theme twice. Does it pick new recipes?
  • “vegan sushi with beef”. Does it explain, or invent?
  • “Antarctic street food”. Does it widen its search?

When things go wrong
You seeTry
401 wrong class keyRe-enter the COORDINATOR_KEY secret. Ask Lovable: “Check that save_recipe sends Authorization: Bearer + COORDINATOR_KEY.”
400 about X-Group“Send the header X-Group: {{GROUP}} on every call to the coordinator.”
400 with reasonsThe coordinator doing its job. If the agent repeats a mistake, paste the reason into Lovable and ask it to update the model’s instructions.
409Your group already saved that recipe for this theme. The agent should pick another.
A CORS errorThe page calls the coordinator directly. “Move save_recipe into a backend function.”
Optional: save over MCP instead of REST

The coordinator is also an MCP server at {{SITE}}/api/mcp (Streamable HTTP, same two headers) with a save_recipe tool. Try it once the REST version works.

Optional promptSwitch save_recipe to MCP
