Build the Recipe Scout

An agent that takes a theme, searches a real recipe database, chooses five recipes that fit, and saves them to the coordinator for the Meal Planners to use.

The goal

Your Scout is done when: you type a theme, press a button, watch it work step by step, and five recipes that fit the theme appear on the Database page under your group.

  • It only saves real recipes it looked up. It never invents one.
  • Each saved recipe passes the coordinator’s checks. When one is rejected, the agent fixes it and retries.
  • The five recipes are varied: not five pasta dishes.
  • You can see every step it took: what it searched, what it read, what it saved.

How it works

An agent is a loop. The AI model decides which tool to use next, your code runs that tool, and the result goes back to the model, until the job is done. The Scout has two kinds of tools:

Finding recipes: TheMealDB

A free recipe database, no key needed. Base address https://www.themealdb.com/api/json/v1/1/

ToolCalls
Search by namesearch.php?s=curry
Filter by ingredientfilter.php?i=chickpeas
Filter by categoryfilter.php?c=Vegetarian
Filter by cuisinefilter.php?a=Italian
Get a full recipelookup.php?i=52772

Filters return only id, name and photo. Use “get a full recipe” before saving.

Saving recipes: the coordinator

Your app’s backend sends each recipe here, with the class key and your group name:

POST {{SITE}}/api/recipes
Authorization: Bearer <class key>
X-Group: {{GROUP}}
Content-Type: application/json

{ …the recipe… }
AnswerMeans
201Saved. The reply includes the stored recipe.
400Something’s missing or wrong. errors lists every problem.
409Your group already saved this recipe for this theme.
401Missing or wrong class key. (400 if X-Group is missing.)

The recipe format

This is the contract between your Scout and every Meal Planner in the class. The coordinator rejects anything that doesn’t match, including fields that aren’t listed here.

FieldRequiredWhat goes in it
themeyesThe theme you searched for, exactly as typed
meal_idyesTheMealDB’s idMeal, e.g. "52772"
nameyesstrMeal
category, cuisinenostrCategory, strArea
ingredientsyesA list built from strIngredient1…20 and strMeasure1…20. Each item: name, amount (a positive number, or null for “to taste”), unit (or null for things you count, like eggs), raw (the original measure text)
instructionsyesstrInstructions (at least 20 characters)
est_minutesyesYour agent’s estimate of the total time: a whole number
est_servingsyesYour agent’s estimate of the servings: a whole number
image_url, source_urlnostrMealThumb, strSource (must start with http:// or https://)
why_chosenyesOne sentence: why this recipe fits the theme
Example of a valid recipe 
{
  "theme": "cheap weeknight vegetarian dinners",
  "meal_id": "52870",
  "name": "Chickpea Fajitas",
  "category": "Vegetarian",
  "cuisine": "Mexican",
  "ingredients": [
    { "name": "chickpeas", "amount": 400, "unit": "g", "raw": "400g can" },
    { "name": "red pepper", "amount": 1, "unit": null, "raw": "1 sliced" },
    { "name": "smoked paprika", "amount": 1, "unit": "tsp", "raw": "1 tsp" },
    { "name": "salt", "amount": null, "unit": null, "raw": "to taste" }
  ],
  "instructions": "Heat the oven to 200C. Toss the chickpeas and pepper with the spices and roast for 20 minutes…",
  "est_minutes": 30,
  "est_servings": 4,
  "image_url": "https://www.themealdb.com/images/media/meals/example.jpg",
  "source_url": null,
  "why_chosen": "Cheap tinned chickpeas, one tray, ready in 30 minutes."
}

A rejected recipe gets every problem at once, for example: est_servings must be at least 1, why_chosen is empty, unknown field: calories.

Build it in Lovable

Paste these prompts into Lovable one at a time. After each one, check the result before moving on. Your app uses Lovable Cloud for its backend and Lovable’s built-in AI for the agent, so you don’t need any API keys except the class key.

The class key never goes in a prompt. Prompt 1 asks Lovable to create a secret. Lovable then shows a secure box where you paste the key.

Pick one name for your group and use it for both agents, e.g. team-3. It labels everything your agents save.

Prompt 1 of 4Create the app and store your key

Build a web app called "Recipe Scout" for a class exercise. It's an AI agent that finds real recipes for a theme and saves them to our class coordinator at {{SITE}}. Enable Lovable Cloud so the app has a backend. Add a secret named COORDINATOR_KEY and ask me to enter its value. It is our class key. Only backend functions may use it: never put it in the page, the browser, or the code. Our group name is {{GROUP}}. Every call to the coordinator must send the header "X-Group: {{GROUP}}". For now, build one page with: - a text box for the theme, with the examples "cheap weeknight vegetarian dinners", "comfort food for a rainy day" and "15-minute lunches" as clickable chips - a "Run Recipe Scout" button - two empty panels side by side: "What the agent is doing" and "Saved recipes"

Prompt 2 of 4Add the tools

Create backend tools the agent will use. Plain code only, no AI yet. Each returns JSON. TheMealDB (free, no key). Base address https://www.themealdb.com/api/json/v1/1/ 1. search_by_name(query) -> search.php?s=QUERY 2. filter_by_ingredient(ingredient) -> filter.php?i=INGREDIENT 3. filter_by_category(category) -> filter.php?c=CATEGORY. Valid categories: list.php?c=list 4. filter_by_cuisine(area) -> filter.php?a=AREA. Valid cuisines: list.php?a=list 5. get_recipe(meal_id) -> lookup.php?i=MEAL_ID. Returns the full recipe. The filter tools only return id, name and photo. Return an empty list (not an error) when TheMealDB finds nothing ("meals": null). The coordinator: 6. save_recipe(recipe) -> POST {{SITE}}/api/recipes with the headers "Authorization: Bearer " + the COORDINATOR_KEY secret, "X-Group: {{GROUP}}", and "Content-Type: application/json", and the recipe as the JSON body. Return the HTTP status and the coordinator's reply exactly as received. When the status is 400 or 409, the reply has an "errors" list saying what to fix. Don't treat that as a crash: pass it back so the agent can fix the recipe and try again. Test tools 1 to 5 once each with a sample input and show me the results. Don't call save_recipe yet.

Prompt 3 of 4Add the agent loop

Now add the agent: a backend function run-scout that uses Lovable AI with tool calling and the six tools. How it runs: - Create a run record with the theme. Send the model the instructions below, the theme, and the tool definitions. - When the model asks for a tool, run it and send back the result. Repeat. - Stop when the model calls finish(summary), or after 25 tool calls, or after 2 minutes. If it stops because of a limit, record why. - Save every step to a table agent_steps (run_id, step number, kind: thought / tool_call / tool_result / error / final, tool name, input, output, time) as it happens, so the page can show them live. Instructions for the model: "You are Recipe Scout. Find 5 real recipes on TheMealDB that fit the theme, and save each one with save_recipe. - Search in several ways (by name, ingredient, category, cuisine). If a search finds nothing, try another one. - Always call get_recipe before saving. Never invent a recipe, an ingredient, or a quantity. - Build the recipe in exactly this format, with no other fields: theme (exactly as given), meal_id (idMeal), name (strMeal), category (strCategory), cuisine (strArea), ingredients, instructions (strInstructions), est_minutes, est_servings, image_url (strMealThumb), source_url (strSource, or null if empty), why_chosen. - ingredients: one item per non-empty strIngredientN, with name (the ingredient, lowercase), amount (the number from strMeasureN, or null if there isn't one), unit (like g, tbsp, cup, or null for countable things like eggs), raw (strMeasureN exactly as written). - est_minutes and est_servings: whole numbers, estimated from the instructions and quantities. - why_chosen: one sentence explaining why it fits the theme. - Choose variety: different main ingredients and cuisines where the theme allows. - If save_recipe returns errors, read every one, fix the recipe, and save again. If it says the recipe is already saved, pick a different one. - When 5 recipes are saved, call finish with a short summary. If the theme contradicts itself or can't be met, explain why and finish early."

Prompt 4 of 4Show the agent working

Connect the page to run-scout. - "Run Recipe Scout" starts a run with the theme and disables itself until the run ends. - "What the agent is doing" shows the steps live, one card per step: thoughts in plain text, tool calls with the tool name and inputs, results collapsed by default (click to see the JSON), errors and coordinator rejections in red. Show a counter like "12 / 25 tool calls". - "Saved recipes" shows each recipe the coordinator accepted: photo, name, cuisine, estimated time and why_chosen. - Add a link "See it on the class database" to {{SITE}}/database - Keep a list of past runs so I can reopen any earlier trace.

Optional: connect over MCP instead

MCP (Model Context Protocol) is a standard way for AI agents to discover and use tools. The coordinator is also an MCP server, so an agent can use its tools directly instead of calling the REST address. Try this once your Scout works over REST.

MCP server{{SITE}}/api/mcp (Streamable HTTP)
HeadersAuthorization: Bearer <class key> and X-Group: {{GROUP}}
Tools for the Scoutsave_recipe (same format and checks as above), list_recipes

Optional promptSwitch save_recipe to MCP

Change how the agent saves recipes: instead of calling the REST address, connect to the coordinator's MCP server from the backend. - Use the official MCP TypeScript SDK (@modelcontextprotocol/sdk) with the Streamable HTTP client transport. - Server address: {{SITE}}/api/mcp. Send the headers "Authorization: Bearer " + the COORDINATOR_KEY secret, and "X-Group: {{GROUP}}". - List the server's tools and give the save_recipe tool to the model, using the input schema the server provides. - When the tool result has isError: true, pass its text back to the model so it can fix the recipe and try again. Keep the TheMealDB tools as they are. Show "via MCP" on tool calls in the trace.

Test it

It works when…

  • A run with “cheap weeknight vegetarian dinners” saves 5 recipes
  • They appear on the Database page under your group, with photos
  • The trace shows each search, look-up and save
  • The Database page’s Activity tab shows your saves as accepted

Now try to break it

  • Run the same theme twice. Does it notice the duplicates and pick new recipes?
  • A contradiction: “vegan sushi with beef”. Does it explain the problem, or invent something?
  • Nothing to find: “Antarctic street food”. Does it widen its search sensibly?
  • A tight limit: set the limit to 8 tool calls. What does it do when it runs out?

When things go wrong

You seeTry
401 “Missing or wrong class key”Check the key on the Welcome page. Then ask Lovable: “Check that save_recipe sends the header Authorization: Bearer followed by the COORDINATOR_KEY secret.”
400 about X-GroupAsk Lovable: “Send the header X-Group: {{GROUP}} on every call to the coordinator.”
A 400 with reasonsThat’s the coordinator doing its job. If the agent keeps making the same mistake, paste the reason into Lovable: “The coordinator rejects our recipes with: … Update the instructions for the model so it gets this right.”
“unknown field: …”The agent added a field that isn’t in the format. Ask Lovable to send only the fields listed on this page.
A CORS error in the browser consoleThe page is calling the coordinator directly. Saving must happen in a backend function: “Move the save_recipe call into a backend function.”
The agent stops early or loopsLook at the last few steps of the trace. Tell Lovable what it did and what it should have done instead.
