Agent 1

Build the Recipe Scout

An agent that takes a theme, searches a real recipe database, chooses five recipes that fit, and saves them to the coordinator for the Meal Planners to use.

The goal

Your Scout is done when: you type a theme, press a button, watch it work step by step, and five recipes that fit the theme appear on the Database page under your group.

  • It only saves real recipes it looked up. It never invents one.
  • It learns the rules from the coordinator (get_expectations) instead of having them written into its code.
  • When the coordinator rejects a recipe, the agent fixes it and retries.
  • You can see every step it took: what it read, searched, looked up and saved.

Build it in Lovable, step by step

Each step says what it adds, then gives a sample prompt. Copy the prompt into Lovable as it is, or edit it to make the app your own, then check the result before moving on. Steps 1 to 3 build a working agent on its own. Step 4 connects it to the class coordinator. Your app uses Lovable Cloud for its backend and Lovable’s built-in AI for the agent, so the only key you need is the class key, in step 4.

Test it

It works when…

  • The trace starts with get_expectations
  • A run with “cheap weeknight vegetarian dinners” saves 5 recipes
  • They appear on the Database page under your group, with photos
  • The trace shows each search, look-up and save
  • The Database page’s Activity tab shows your saves as accepted

Now try to break it

  • Run the same theme twice. Does it notice the duplicates and pick new recipes?
  • A contradiction: “vegan sushi with beef”. Does it explain the problem, or invent something?
  • Nothing to find: “Antarctic street food”. Does it widen its search sensibly?
  • A tight limit: ask Lovable to set the limit to 8 tool calls. What does it do when it runs out?

Reference

How it works

An agent is a loop. The AI model decides which tool to use next, your code runs that tool, and the result goes back to the model, until the job is done. The Scout has two kinds of tools.

Finding recipes: TheMealDB

A free recipe database, no key needed. Base address https://www.themealdb.com/api/json/v1/1/. It publishes notes for AI agents: AGENTS.md, SKILL.md and the API documentation.

Saving recipes: the coordinator’s MCP server

MCP (Model Context Protocol) lets an agent discover tools and their rules from a server instead of having them written into its code. {{SITE}}/api/mcp?agent=scout offers the Scout three tools:

ToolDoes
get_expectationsThe goal, the rules, every field save_recipe accepts (and where its value comes from in TheMealDB), and an example
save_recipeSaves one recipe under your group, or rejects it with every reason at once
list_recipesWhat the class has saved so far

Every request carries Authorization: Bearer <class key> and X-Group: {{GROUP}}. Under the hood it’s one POST per call:

POST {{SITE}}/api/mcp?agent=scout
{ "jsonrpc": "2.0", "id": 1, "method": "tools/call",
  "params": { "name": "get_expectations", "arguments": {} } }
The recipe format (your agent reads this from get_expectations)

The contract between your Scout and every Meal Planner. The coordinator rejects anything that doesn’t match, including fields that aren’t listed here.

FieldRequiredWhat goes in it
themeyesThe theme, exactly as typed
meal_idyesTheMealDB’s idMeal, e.g. "52772"
nameyesstrMeal
category, cuisinenostrCategory, strArea
ingredientsyesOne item per strIngredientN: name, amount (a positive number, or null for “to taste”), unit (or null for things you count, like eggs), raw (strMeasureN as written, or "" when TheMealDB gives no measure)
instructionsyesstrInstructions (at least 20 characters)
est_minutes, est_servingsyesThe agent’s estimates: whole numbers
image_url, source_urlnostrMealThumb, strSource (http/https, or null)
why_chosenyesOne sentence: why this recipe fits the theme

A rejected recipe gets every problem at once, for example: est_servings must be at least 1, why_chosen is empty, unknown field: calories.

When things go wrong
You seeTry
401 “Missing or wrong class key”Re-enter the COORDINATOR_KEY secret. Then ask Lovable: “Check that every request to the coordinator sends Authorization: Bearer followed by the COORDINATOR_KEY secret.”
400 about X-Group“Send the header X-Group: {{GROUP}} on every request to the coordinator.”
The agent never calls get_expectations, or the tool is missing“Load the coordinator’s tools with tools/list from {{SITE}}/api/mcp?agent=scout and give all of them to the model.”
A rejection with reasonsThat’s the coordinator doing its job. If the agent keeps making the same mistake, paste the reason into Lovable: “The coordinator rejects our recipes with: … Make sure the agent passes the rejection text back to the model.”
“unknown field: …”The agent added a field. Ask Lovable to send exactly what get_expectations lists.
A CORS error in the browser consoleThe page is calling the coordinator directly. “Move every call to the coordinator into a backend function.”
The agent stops early or loopsLook at the last few steps of the trace. Tell Lovable what it did and what it should have done instead.
Without MCP: save over REST

The same checks are also available as a plain REST address, if MCP gives you trouble.

POST {{SITE}}/api/recipes
Authorization: Bearer <class key>
X-Group: {{GROUP}}
Content-Type: application/json

{ …the recipe… }
AnswerMeans
201Saved. The reply includes the stored recipe.
400Something’s missing or wrong. errors lists every problem.
409Your group already saved this recipe for this theme.
401Missing or wrong class key. (400 if X-Group is missing.)

Over REST the agent can’t read the rules itself, so the recipe format has to go into the model’s instructions.
