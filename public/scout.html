Agent 1

Build the Recipe Scout

An agent that takes a theme, searches a real recipe database, chooses four recipes that fit, and saves them to the coordinator for the Meal Planners to use.

Build it in stages

You’ll build Recipe Scout in stages. First, you’ll create a simple interface. Then you’ll connect it to real recipe information, add an AI agent, and connect that agent to the class coordinator.

You will change and rework parts of the app as you go. That is intentional. The goal is to understand how the system develops—not to build the perfect application on the first attempt.

Working in Lovable

  1. Start a new project: in Lovable, go to Projects → New project. The Recipe Scout gets a project of its own, separate from the Meal Planner.
  2. Follow the steps below. Each step has a goal, a sample prompt to copy into Lovable (use it as it is or change it), what you should see, and things you can try before moving on.
  3. Use Build mode. Make sure Lovable is set to Build when you paste a prompt, so it writes the code. In Plan mode it only talks the change through.
  4. Approve Cloud. If Lovable asks to enable Cloud, approve it: the app needs a backend to reach recipes and the coordinator.

Step 0 · warm-upBuild your first page

Goal

See how quickly Lovable can turn a plain-language description into an interface. There is no AI, backend or recipe data yet.

Sample prompt

What you should see

A finished-looking page with a theme input, example themes, a button and an empty results area. It is normal that the button does nothing.

Things you can try

  • Ask Lovable to change the colors or visual style.
  • Add another example dinner theme.
  • Change the title or button text.
  • Ask Lovable to make one small layout improvement.

Don’t spend too long polishing. You will change the interface as the agent develops.

Step 1Connect to real recipe information

Goal

Give the application reliable actions for finding real recipes. These are ordinary backend functions—not an AI agent.

Sample prompt

What you should see

  • The original Recipe Scout page
  • A temporary Recipe Tool Lab
  • Real recipes returned from TheMealDB
  • Ingredients and instructions when retrieving a complete recipe

Things you can try

  • Search by name for Arrabiata.
  • Search using the ingredient chicken.
  • Browse the category Vegetarian or the cuisine Italian.
  • Search for something that probably does not exist.

Notice the difference between an action and an agent. An action performs one specific task. An agent decides which actions to use and in what order.

Step 2Add the Scout Agent

Goal

Add an AI agent that decides how to search, examines the results and selects four recipes. This is the first step with a “What the Scout Agent is doing” panel.

Sample prompt

What you should see

  • The Scout Agent decides how to search and leaves traces of its behavior
  • Four selected recipes with photos and explanations
  • A clear explanation if the Scout Agent cannot finish

Things you can try

  • Comfort food
  • 20-minute vegetarian dinners
  • Vegan dinners with beef
  • Antarctic street food

The important question is not only “Did it find four recipes?” Also ask: “What did it try, and did its choices make sense?”

Step 3Join the multi-agent system

Goal

Connect Recipe Scout to the class coordinator so its recipes can be checked, saved and passed to other agents, such as the Recipe Pricer and the Meal Planner.

Recipe Scout → Coordinator → Recipe Pricer

The Scout Agent does not send recipes directly to the Recipe Pricer. It sends them to the coordinator. The coordinator checks each recipe, saves accepted recipes and makes them available to the next agent.

The Scout Agent talks to the coordinator through MCP, a standard way for an app to ask another system what actions it offers and then use them.

Step 3aConnect to the coordinator

Goal

Connect the app to the coordinator’s MCP server and look at the actions (tools) it offers.

The class key never goes in a prompt. This step asks Lovable to create a secret. Lovable then shows a secure box where you paste the key.

Sample prompt

What you should see

  • A successful connection message, with your group name as the coordinator confirms it
  • The tools provided by the coordinator and a description of what each tool does
  • No change to the Scout Agent’s behavior yet

Things you can try

  • Read the description of each coordinator tool, and the information each one requires.
  • Look for your connection on the Coordinator page.
  • Discuss which tool the Scout Agent should use first.
  • Discuss which tool it would use to hand off a recipe.

MCP allows an application to discover what another system can do. The coordinator describes its tools, so Recipe Scout does not need to have their names and input formats written into its code.

Step 3bLet the Scout Agent use the coordinator

Goal

Give the discovered coordinator tools to the Scout Agent. The Scout Agent will learn how to work with the coordinator, submit recipes, respond to rejections and complete the handoff so that other agents can use the recipes.

Sample prompt

What you should see

  • The Scout Agent follows the formats, rules and limits returned by the coordinator.
  • It searches and examines real recipes through TheMealDB and submits recipes to the coordinator.
  • Accepted and rejected submissions are clearly identified and the Scout Agent tries to correct rejected recipes.
  • Four accepted recipes appear on the Coordinator page and the Recipe Pricer queues or begins processing the accepted recipes.

Things you can try

  • Run the same theme twice and observe duplicate handling.
  • Try a contradictory theme.
  • Open a rejected exchange on the Coordinator page and compare it with an accepted one.
  • Change one Scout Agent instruction and compare its behavior.

Each group can save a limited number of recipes in total (the coordinator tells your agent how many), so plan your runs: once the limit is reached, further saves are rejected.
